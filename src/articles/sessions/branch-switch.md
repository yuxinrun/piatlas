## 技术背景

usage.md 明确列出 /tree、/fork、/clone：/tree 探索不同会话分支，/fork 从当前会话分叉，/clone 克隆会话。
extensions.md 的 ExtensionCommandContext 额外方法有 newSession、fork、navigateTree、switchSession、reload；这些是扩展作者可调用的入口。

## 核心原理

回退不是“撤销文件”，而是把当前条目移动到较早节点。之后的新消息会成为同一文件中的新分支。
fork 与 clone 则改变存储边界：它们把选定历史复制到新会话文件，适合在不影响原会话的情况下尝试高风险方案。

## 实际执行过程

1. 在测试会话中制造两个分支，记录各自消息数。
2. 用 /tree 切换当前路径，观察下一次回答的差异。
3. 用 /fork 创建新会话，确认原会话未改变。
4. 在切换前记录已发生的外部副作用，避免误以为回退会撤销它们。

## 设计优点与局限

- 优点：探索成本低；原路径与审计信息保留。
- 局限：外部副作用不会随分支回退；分支多了容易迷失。

## 容易出现的问题

- 以为切换分支会撤销文件修改。
- 把 fork 当成重命名会话。
- 在切换后沿用旧会话的订阅与缓存。

## 实战案例

设计“方案 A 用只读工具，方案 B 用写入工具”的分支；从同一父节点出发，对比两种结果的副作用清单。

## 最佳实践

高风险尝试先 fork；切换后立刻用 /session 核对；把重要节点命名。

## 常见问题

### 回退会撤销工具做过的修改吗？

不会。分支只改变会话历史，不改变外部系统状态。

### fork 与 clone 相同吗？

官方都描述为复制到新会话文件；操作对象和默认范围请按当前版本文档核验。
