## 技术背景

usage.md 确认 /login 与 /logout 管理 provider 登录；containerization.md 说明不同沙箱里的凭据位置差异：Plain Docker 环境变量进入容器，Docker Sandboxes/OpenShell 可让真实凭据留在宿主机侧。
README 说明 Pi 不内置凭据访问限制，因此密钥管理必须依赖进程边界、用户权限与轮换流程。

## 核心原理

密钥生命周期包含四个动作：最小权限生成、短期使用、定期轮换、可验证撤销。任何一步缺失，都会让“它曾经能跑”变成长期风险。
检查日志与会话分享时，重点是“密钥是否以文本形态进入可复制位置”：shell history、导出文件、调试日志、截图和聊天记录。

## 核心代码解释

```bash
# 凭据检查清单（命令本身不读取密钥值）
# 1. 只确认是否存在，不打印内容
test -n "$EXAMPLE_API_KEY" && echo configured || echo missing

# 2. 在 Pi 内使用官方登录/登出命令
pi
/login
/logout

# 3. 分享前检查导出文件是否包含 key-like 字符串
rg -i "api[_-]?key|token|secret" ./export.jsonl
```

EXAMPLE_API_KEY 是占位；请以你的 Provider 文档为准。第二条 rg 只用于本地排查，命中不等于一定泄露。

## 实际执行过程

1. 为实验与生产分别创建密钥。
2. 在 Pi 中通过 /login 配置，并记录配置日期。
3. 每次会话分享前运行脱敏检查。
4. 任务结束轮换实验密钥。
5. 在 Provider 控制台确认旧密钥已撤销。

## 设计优点与局限

- 优点：生命周期清晰；泄露影响可控。
- 局限：轮换需要流程纪律；多环境管理复杂。

## 容易出现的问题

- 把密钥写进 SKILL.md 示例。
- 截图时露出终端中的密钥。
- 长期沿用同一个测试密钥。

## 实战案例

设计一张密钥登记表：用途、环境、创建日期、最后使用、轮换负责人；不要记录密钥本体。

## 最佳实践

最小权限、短期有效、默认脱敏；把轮换纳入月度检查。

## 常见问题

### Pi 会帮我撤销密钥吗？

不会；撤销在 Provider 侧完成。

### /logout 够吗？

它管理 Pi 侧登录状态；仍建议按 Provider 流程撤销不再使用的密钥。
