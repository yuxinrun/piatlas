## 技术背景

how-pi-works.md 明确说明：prompt templates 在编辑器输入成为 user message 之前展开；扩展可以添加指令或转换上下文。coding-agent 的公开入口包含 PromptTemplate 与 parseSkillBlock 等导出。
已核验文档没有给出模板文件的完整字段规范，因此本文只写“展开时序”和“设计原则”，不虚构具体 YAML 字段。

## 核心原理

模板的价值是把稳定结构从重复输入中抽离：目标、约束、证据要求、输出格式。它不应替代对当前任务的判断。
展开发生在输入进入 agent 之前，因此模板文本会变成用户消息或上下文的一部分；扩展的 input 事件可在 skill/template 展开前处理原始输入。

## 核心代码解释

```typescript
// 教学模板：不是 Pi 官方模板文件格式
const template = (task: string) => [
  "目标：" + task,
  "证据：先列出读取过的文件，再给结论",
  "限制：不做写入；不确定处标记待核验",
  "输出：结论 / 证据 / 未解决问题"
].join("\n");

const userMessage = template("统计目录中的 Markdown 文件");
```

## 实际执行过程

1. 把重复出现的约束写成模板文本。
2. 先用手工粘贴验证效果，再考虑做成资源。
3. 确认模板展开后不会被二次展开。
4. 让扩展只做必要转换，不隐藏用户输入。

## 设计优点与局限

- 优点：减少重复；提高输出结构一致性。
- 局限：模板过长会占上下文；错误模板会影响所有任务。

## 容易出现的问题

- 把未核验字段当官方格式。
- 在模板中塞入凭据。
- 把模板当成权限控制。

## 常见问题

### 模板何时展开？

how-pi-works.md 说在编辑器输入成为 user message 之前。

### 模板能拦截输入吗？

拦截是扩展 input 事件的能力，不是模板本身的职责。
