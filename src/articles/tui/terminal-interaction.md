## 技术背景

usage.md 明确列出：Enter 发送、Shift+Enter 换行、Ctrl+G 外部编辑、@ 搜索文件、Tab 补全路径；运行中可输入消息影响下一步，Alt+Enter 排队 follow-up，Alt+Up 取回排队消息，Escape 停止。
同一文档还列出 /model、/thinking、/settings、/tree、/compact、/export、/debug 等命令，以及 ! 与 !! 的终端命令行为。

## 核心原理

终端交互设计的重点是“状态可见”：当前是运行中、排队中还是空闲？哪些消息会在当前 turn 后生效？哪些会在完成后生效？快捷键必须让用户能控制这些状态。
Windows Terminal 会占用部分 Alt 快捷键；官方提示见 terminal-setup。教程应提醒读者按自身终端验证。

## 实际执行过程

1. 在临时目录启动 Pi，测试 Enter 与 Shift+Enter 的差异。
2. 用 @ 加入文件，观察消息内容变化。
3. 运行中执行 !git status，观察输出何时出现。
4. 输入 follow-up 并用 Alt+Up 取回。
5. 用 Escape 停止一次长任务。

## 设计优点与局限

- 优点：键盘路径短；运行态可干预；状态提示丰富。
- 局限：快捷键多；终端差异会影响体验。

## 容易出现的问题

- 把 follow-up 与 steering 混为一谈。
- 在 Windows Terminal 中照搬所有 Alt 键。
- 用 ! 执行会产生副作用的命令。

制作一张键位卡片，分成“输入、运行控制、视图、会话”四组，并在团队内试用一周。

## 常见问题

### ! 和 !! 有什么区别？

usage.md 说前者输出加入对话，后者输出不发送给模型。

### 如何查看当前快捷键？

使用 /hotkeys。
